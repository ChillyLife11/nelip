# Запись другого человека — 0.22.0

25.11.2026 API установлен на VDSka и проверен. Этот фронтенд пока находится
в ветке форка; для выпуска требуется объединение с основным проектом.

Только Нелип, company_id=4. Лезнову (company_id=6) не трогать.

Чекбокс находится в существующем окне подтверждения. При включении вводятся
фамилия, имя, необязательное отчество и телефон другого пациента. Данные
владельца хранятся отдельно; выключение чекбокса восстанавливает его ФИО.
При новой записи данные другого пациента очищаются.

## Контракт API

Сначала `POST /api/user/register-patient`, Bearer владельца аккаунта:

```json
{
	"company_id": 4,
	"request_key": "UUID текущей регистрации",
	"first_name": "Имя",
	"last_name": "Фамилия",
	"second_name": "",
	"phone": "79991234567"
}
```

Ответ: `{client_id, booking_token}`. Не вызывает `setSession`, не возвращает
access_token, не передаёт MAX ID. Телефон не используется для входа в существующую
карточку: создаётся новая. Тот же request_key и те же данные возвращают тот же ID;
изменившиеся данные требуют нового ключа. Фронтенд делает это автоматически.

Далее обычный `POST /api/appointment/create` с Bearer владельца, но с полученными
`client_id`, `booking_token` и ФИО пациента. Разрешение действует 24 часа, только
для создавшего пациента клиента Нелип. Обычная запись идёт по прежнему пути.

Серверная часть: ветка `ruki/nelip-patient-2304` в `garmayev/medix`.
Фронтенд нельзя выпускать раньше этой серверной части. Миграция БД не нужна.
Авторизация по токену обязательна; административная сессия с company_id не подходит.
Данные другой компании, существующие MAX-привязки и профиль владельца не меняются.

Запись относится к новому пациенту; в истории владельца она автоматически не
появляется, и MAX-уведомления новому пациенту не отправляются без его собственной
MAX-привязки. Управление зависимыми пациентами не добавлялось.
